# Castle

A modern, **free** web terminal that tracks investment banking activity using public **SEC EDGAR** data.
The founder is a finance student building toward IB/PE. Design is set; the job is to build it cleanly.

## The five core features

1. **Deal flow**: announced M&A involving US public companies (acquirer, target, value, price per share, premium, cash/stock, sector, status).
2. **Deal volume**: line charts of M&A $ value and deal count over time, by sector.
3. **IPO pipeline**: companies that filed to go public, by stage (Filed → Priced → Trading), with underwriters.
4. **Who's advising**: league tables of banks by deals advised and value.
5. **Valuation moves**: median EV/EBITDA, EV/Revenue, and premiums paid by sector over time.

**World Economies** (a sixth page, not one of the core five) shows GDP growth and inflation from the IMF World Economic Outlook (DataMapper API; the current year is an IMF estimate) and central-bank policy rates from the BIS, for 11 major economies. Both sources are free and need no key. The data is fetched by the same ingest job (`ingest/macro.ts`) and stored in Supabase `meta` under key `macro`, so no schema change was needed.

## Hard constraints

- **$0 to run.** Free tiers only: Next.js on Vercel, Supabase free Postgres, GitHub Actions, free SEC EDGAR data. No paid APIs or data vendors.
- **Serious, modern finance aesthetic.** Monochrome, dense, calm. The castle appears **only** as the logo (`public/castle-logo.png`, a white crest + CASTLE wordmark on transparent, 1094 × 838, trimmed to the artwork; never use a logo file with a baked-in background). The sidebar draws it in `components/shell/BrandLogo.tsx` as the crest and six letters clipped from that one image (box coordinates in the file: update them if the artwork changes): they rise in on load; a click presses it with a sheen and a crest echo, and quick repeated clicks flip the letters like a departure board (every 3rd) and lift the crest with a wave of echoes (from the 6th). `app/favicon.ico` and `app/apple-icon.png` are the crest on a dark tile.
- **Never commit secrets.** Real values go in `.env.local` (git-ignored). Document every variable in `.env.example` with no values. Supabase service-role keys stay server-side / in GitHub Actions secrets, never `NEXT_PUBLIC_`.
- SEC EDGAR requires a descriptive `User-Agent` with contact info and has a rate limit of 10 requests/second.

## Design reference

`Design/Castle_Hub.html` is the approved design (v2, a multi-page terminal made in ChatGPT, standalone HTML with sample data). Match its look, layout, and interactions closely.
`globals.css` keeps the design file's class names (`.panel`, `.kpis`, `.preview-row`, `.detail-drawer`...) so the two are easy to compare. Check the design before changing any visual.
`Design/Castle_Hub_v1.html` is the previous design, kept for reference only.

Design v2 was built in two phases on the `design-v2` branch, both done:
- **Phase 1:** look, logo, 7-page routing, detail drawer, search dropdown, per-page export, definitions.
- **Phase 2:** deal screener (advanced filters, chips, saved views, columns, bulk select, compare), watchlist and notes, right-click and "…" row menus, density and animation settings, "?" shortcuts, chart type and granularity options, IPO and advisor extra filters.

**Workspace data (watchlist, notes, saved views, columns, density) lives only in the browser's localStorage** (`components/workspace/store.ts`, key `castle-workspace-v1`). Nothing is sent to a server. Syncing across devices would need user accounts, which aren't built.

## Commands

```bash
npm run dev      # http://localhost:3000
npm run build    # production build (also type-checks)
npm run lint
npm test                               # vitest: parsers, financials, aggregation
npm run test:pages                     # after a build: every page in Chrome (Playwright), desktop + phone; CI runs it
                                       # (CASTLE_DATA_SOURCE=sample npm run build first to test as CI does, on sample data)
npm run ingest -- --local              # pull the last 5 days of EDGAR into .data/castle.json
npm run ingest:backfill -- --local     # 24-month backfill (resumable; set EDGAR_CACHE_DIR=.data/cache)
npm run ingest                         # same, but writes to Supabase when its env vars are set
npm run ingest -- --only macro         # just World Economies (IMF + BIS), ~1 second
npm run ingest -- --only prices        # merger-arb spreads + buyers' share-price reactions (Yahoo, no key), a few minutes
npm run ingest -- --skip macro         # everything except the named step(s), comma-separated
npm run ingest -- --only deals --rebuild-deals --from 2024-09-01   # re-read all filings with current parsers; drops stale deals at the end
npm run ingest -- --only deals --backstop-only --from 2021-01-01   # only look up merger-proxy filers without a deal (after a backstop / 8-K parser change)
                                       # (also a "rebuild" checkbox on the GitHub Actions "Run workflow" form)
npm run audit                          # data-quality audit of the live database (read-only); -- --local, -- --all
npm run audit -- --max-flagged 3 --max-age 8   # exit 1 if >3% flagged or data >8h old (ingest.yml and monitor.yml run this)
npm run history -- report              # history foundation (what-if engine): see "History foundation" below
npm run ripple -- --shock Tech.valuation=10 --shock vix=10   # what-if ripple engine (read-only), see "Ripple engine" below
npm run estimate                       # re-estimate the ripple links from the history (Python), see "Link estimation" below
npm run backtest                       # out-of-sample backtest; re-tunes the engine (tuned.json), see "Backtest" below
```

With Supabase keys in `.env.local`, the local site reads the live database. Set `CASTLE_DATA_SOURCE=local` (in the shell or `.env.local`) to make it read `.data/castle.json` instead, e.g. to try ingest changes without touching production.

Going live (Supabase, GitHub secrets, Vercel) is documented step by step in [SETUP.md](SETUP.md).

### Data rules (important)

- Components **never** import `lib/sampleData.ts` or `ingest/`. They read `HubData` through `useHubData()`, which the terminal layout fills from `getHubData()`.
- **The deployed site never shows sample data.** On Vercel, if Supabase can't be read, `getHubData()` returns empty data with `dataError` and the shell shows a red banner saying why. Sample data exists only for local development before anything is ingested.
- Stored records are the `Deal` / `Ipo` shapes plus ingest-only fields (`StoredDeal`/`StoredIpo` in `ingest/store.ts`); `lib/aggregate.ts` strips those before data reaches the browser. **The dataset reaches the browser once per visit from `GET /api/hub`** (static, regenerated at most once a minute, compressed, browser-cached 10 minutes with stale-while-revalidate) and stays in memory in `HubDataProvider`; the terminal layout passes only a small boot copy (`bootHubData`: no deals / IPOs / activists / fees). Never pass the full `HubData` through a layout or page again: it shipped ~2.3 MB with every page and every navigation, which on a slow connection meant minutes per click. Until the dataset arrives the page is hidden behind `PageSkeleton`, and clicks are held and replayed (`NavigationProgress hold`). Fairness opinions stay out of the feed (`hasFairness` flag; loaded from `/api/deal/[id]`), and so do all but each deal's first filing (`filingCount`): the drawer's Filings tab and company pages fetch the full record through `useFullDeal` / `fetchFullDeal` (`components/data/useFullDeal.ts`, cached per visit). The terminal layout preloads `/api/hub` (`preload` from react-dom) so the dataset downloads in parallel with the JavaScript instead of after it; HubDataProvider's plain `fetch("/api/hub")` reuses the preloaded response (keep the two matching). October 2026 measurements: ~300 KB of JavaScript and ~330 KB of gzipped data per first visit.
- Freshness: ingest hourly on weekdays (quick run, `--skip macro,prices`) and every 6 hours (full run). Pages and `/api/hub` regenerate at most once a minute: the shared meta cache in `lib/data.ts` is 60 s, which caps the routes' own `revalidate` (900 / 120). A regeneration is a cache hit unless `asOf` changed. The private repo's 2,000 free Actions minutes cover roughly this cadence; a public repo would allow every 15–30 minutes. Volume charts cover as many months as the data has (24–72).
- **A new deal field shown on the site must be added to `DEAL_FIELDS` in `lib/data.ts`** (the Supabase read selects only those) as well as to `toPublicDeal`; local JSON reads have every field, so a missing one only shows up on the live site.
- **Data cache (performance):** `lib/data.ts` reads Supabase through `unstable_cache`. Meta is re-checked every minute; deals (in 500-row chunks, because Next caps an entry at 2 MB) and IPOs are cached per `asOf` snapshot and shared by every page. Only the fields the site uses are selected. Reads retry transient errors. On Vercel a failed refresh throws, so the last good page keeps being served instead of an empty one. Never make each page read the database on its own: eleven pages × 8 s used to make clicks wait up to a minute.
- **Live updates without a refresh:**
  - `HubDataProvider` polls `GET /api/freshness` (edge-cached 30 s) 3 s after load, then every 30 s while the tab is visible, and again when the tab regains focus or the network returns. When the database `asOf` is newer, it re-fetches `/api/hub?t=…` (no-store; up to 6 tries per new dataset while the cached copy catches up) and swaps the data in place.
  - It must **never** call `revalidatePath` / `revalidateTag` from user traffic. An earlier version did, purging every cached page and making each click wait for a full rebuild.
  - What the user sees: the top-bar `LiveStatus` pill ("Live · updated N min ago"; "2 new deals" / "1 new IPO" / "Updated" for 8 s after an update), new deal / IPO rows glow green for 12 s (`freshness.freshIds`, `.row-fresh`), changed KPI figures count to their new value tinted green / red (`isLiveUpdate()` in `AnimatedNumber`), and charts ease to new values.
- **Navigation feedback:** `NavigationProgress` draws a hairline progress bar from the click until the new page shows.
- UI copy (badges, notes, footer, methodology) switches on `HubData.isSample`.
- Conventions in `lib/types.ts`: money is plain USD, dates are ISO strings, percentages are whole numbers (34.2 = 34.2%), `null` means undisclosed.
- KPIs, momentum and medians are computed in `lib/metrics.ts` from raw rows. Never hardcode derived numbers in the UI.
- Sample bank names are real institutions, but their activity and ranks are fictional. Keep them labelled as sample data.

The desktop layout stays dense. No page may scroll sideways at 375px.

### Reliability

- **Page smoke test** (`e2e/pages.e2e.ts`, `playwright.config.ts`, `npm run test:pages` after a build): every page in `ROUTES`, at 1366px and 375px, must load its data (skeleton gone, no load error), show a heading and content, not scroll sideways, and log no exceptions or console errors; plus a deal drawer, a company page, a tear sheet, the feed, freshness, sitemap, robots and preview image. It uses the installed Chrome (`channel: "chrome"`, preinstalled on GitHub's runners; installed with `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`, no browser download). CI runs it on sample data (`CASTLE_DATA_SOURCE=sample` reproduces that locally). Its first run caught a hydration error on every page: the top bar's "updated N min ago" was rendered with the build's clock (`LiveStatus` now starts its clock after hydration). Never render the current time on the server.
- **Data quality and freshness:** `npm run audit -- --max-flagged 3 --max-age 8` exits 1 (with `::error::` annotations) past either limit. The ingest workflow runs it (quality) after every ingest, and `.github/workflows/monitor.yml` once a day (quality and freshness), so GitHub emails when quality slips or updates stop.
- **Rebuild saves:** deal ids are unique (a second deal for the same target and day gets `-2`; rival buyers can announce the same day), `SupabaseStore.save` writes one row per id, and a failed progress save (`checkpoint` in `ingest/run.ts`) is logged, not fatal. A repeated id once stopped a rebuild an hour in ("ON CONFLICT DO UPDATE command cannot affect row a second time"), leaving a half-rebuilt, unpruned database. Local JSON runs don't catch this, since the JSON store accepts repeated ids.
- **Visible staleness:** data older than 8 hours (`STALE_AFTER_MS` in `LiveStatus.tsx`; full runs are every 6 hours) turns the top-bar pill amber: "Delayed · updated N h ago".

### Sharing and search

- **Screens are links.** Deal Flow and Precedents write their filters to the URL (`lib/urlState.ts`: only non-default fields, every value validated on the way back in; specs `DEAL_SCREEN_SPEC` in `lib/screen.ts`, `PRECEDENT_SPEC` in `lib/precedents.ts`), so "/deal-flow?sector=Tech&min=5&sort=value" opens that screen. The watchlist filter stays out (it's the viewer's own); Precedents also carries ?deal= and the unticked outliers (?x=). Their pages wrap the view in `<Suspense>` (client-side `useSearchParams`). A "Link" button (`CopyLinkButton`) copies the address.
- **A deal's shareable page is its tear sheet** (`/tearsheet/deal/[id]`): the drawer's link icon copies it.
- **Link previews:** `metadataBase` from `SITE_URL` (`lib/site.ts`: `NEXT_PUBLIC_SITE_URL`, else Vercel's production domain), Open Graph + `summary_large_image` cards. Images are generated by `opengraph-image.tsx` routes through `ogCard` (`lib/ogCard.tsx`, black card with the logo, a kicker, a title, up to four figures): the site default, deal tear sheets (parties, value, premium, status) and company pages (its acquisitions, or the sale it's in). A page that sets its own `twitter` metadata must repeat `card: "summary_large_image"` (it replaces, not merges).
- **Search engines:** `app/sitemap.ts` (every page, company page and deal tear sheet; ~7,000 URLs) and `app/robots.ts` (all but `/api/`).

### UI conventions (from the October 2026 polish pass; the founder wants clean, organised and professional, never cluttered, and no features removed)

- **Page order:** `PageHeading` (title, subtitle, Export) → `Kpis` → optional `Takeaways` → panels → `AboutData`. The data date lives only in the top bar's live pill, not in headings.
- **`Takeaways`** (primitives): 2–5 short, number-led lines (about 100 characters each) that add something the KPIs don't show. No textbook explanations there; those go in **`AboutData`** (a folded "About this data" disclosure), along with the methodology.
- **Long tables** show `TABLE_PAGE` (25) rows plus `ShowMore` (`components/ui/table.tsx`).
- **Missing values** are always "—" (from `lib/format.ts`).
- **Numbers go through `lib/format.ts`** (`formatPct`, `formatPrice`, `formatMultiple`, `formatUsd`), never `toFixed` in a view or tear sheet, so a premium reads "34.2%" everywhere. A local helper may wrap them (`pct` in Activists / Deal Terms / Economies) but not re-implement them.
- **Column names are the same on every table:** ACQUIRER (not buyer), TARGET, DEAL VALUE (not value / size), ADVISOR (not bank), DEALS ADVISED.
- **Company names** go through `displayCompanyName` (`lib/names.ts`) in `toPublicDeal` / `toPublicIpo`. It strips SEC state tags and title-cases all-capital names. The ingest uses the same `titleCaseCaps`.
- **Controls:** keep a panel to a few visible controls; rarely used options go in a menu (`openMenu`), like the volume chart's ⚙ (chart style, period, gridlines). The volume legend doubles as the month-on-month scoreboard.
- **Navigation:** seven sidebar sections (Hub, M&A, Valuation, Advisors, IPOs, Macro, What-if; `SECTIONS` in `components/shell/routes.ts`; Alt+1–7). A section with several pages shows them as tabs above the page (`SectionTabs`, sliding underline); Hub = Hub · Coverage (`/coverage`), M&A = Deal Flow · Volume · Deal Terms · Timelines · Activism, Valuation = Multiples · Precedents, What-if = Scenarios (`/what-if`) · Accuracy (`/what-if/accuracy`). The sidebar link returns to the tab last open in that section. `routeForPath` takes the longest matching href, so sub-pages work. What-if got its own section at the founder's request; otherwise add a new page to an existing section rather than a new sidebar item.
- **Motion:**
  - page sections rise in one after another (`.page-enter > *`);
  - KPI and valuation figures count up (`AnimatedNumber`, only after hydration, so the first load never flashes);
  - charts grow in, table rows fade in, and hovers and tabs transition.
  - Everything respects the animations setting (`.reduce-motion`) and `prefers-reduced-motion`.

### SEC data engine rules

- **$0:** extraction is regex/heuristics over filing text. No paid APIs, no LLM calls.
- **Never guess:** if a term isn't clearly stated, leave it `null`. Blank is better than wrong.
- **Deal scope:** (1) targets that are SEC registrants listed on a US exchange (NYSE / Nasdaq / NYSE American / Cboe), and (2) **private companies bought by a US-listed acquirer** (`Deal.privateTarget`, id `p-<name>-<date>`). SPAC combinations, investment funds (closed-end funds, ETFs; `FUND_TARGET`), OTC / foreign-listed targets, minority stakes, carve-outs of a named company's business ("acquires Honeywell's valve unit") and asset / product-rights purchases are skipped.
- **Private targets:** found by extra full-text searches ("has acquired", "completed the acquisition of", "definitive agreement to acquire", …; `PRIVATE_QUERIES`). A target counts as private when it resolves to no SEC registrant, has no ticker, passes `isPrivateTargetName`, and no public deal already tracks it by the same name (`identicalNames`, not the loose `sameCompany`: "Apex Crypto" is not Apex Global Brands, "Bank Leumi USA" not Bank of Commerce Holdings; catches delisted public targets; a tracked deal that closed or ended over a month earlier doesn't count, since the same name can be bought again: Hampton Roads bought Xenith in 2016 and took its name, Union Bankshares bought that Xenith in 2017). Every candidate is also looked up with EDGAR's company-name search (`lookupCompanies`, by the full name, by `coreName` without trailing descriptors, and without the legal suffix: "Equitrans Midstream Corporation" finds nothing, "Equitrans Midstream" finds EQUITRANS MIDSTREAM CORP): if it was an exchange-listed reporting company then (`listedOn`: periodic reports in the prior year, still listed, or a Form 25 after; `listedThen` also accepts an 8-K Item 3.01 delisting notice that names Nasdaq / NYSE / Cboe, since OTC companies file Item 3.01 at a closing too: Kentucky Bancshares and Endo, both OTCQX), it becomes a public-target deal (Abiomed, Hillrom, Enable Midstream). The registrant's name on the deal date must match (`registrantMatches`: the same name ignoring spacing and suffixes, or that name plus descriptors only, "Group of Companies" included for Interpublic, so "Fortune" is not Fortune Brands, "Beacon" is not Beacon Financial, and a private "First American" bank is not First American Financial; a short form of three letters only matches exactly: Pulmatrix's "Eos", Eos SENOLYTIX, is not Eos Energy Enterprises), and it must have been in the middle of being bought (`takenOverAround`: merger proxy, tender response, 425 / DEFA14A or Form 25 within ~18 months before to ~13 after; "Longboard" is not Longboard Pharmaceuticals, "API" is not APi Group). A converted record created from a completion release (`completedAround`: the target's Form 25 / 15 within days of the stored date) gets its real announcement date from the signing 8-K Item 1.01 naming the other party, the target's or else the buyer's (`signingDate`, up to ~21 months back; Capital One / Discover → February 2024, AMD / Xilinx → October 2020, not the closings). It's the 8-K filing date, which can trail the press release by a day or three. Don't infer the date from DEFA14A / 425 alone: annual meetings and a company's own earlier mergers file those too. With a premium but no listed registrant it is OTC / foreign, or a release read backwards ("GenMark acquires Roche"), and is skipped; a per-share price alone stays private (private banks quote one). Stored private deals are re-checked whenever `REGISTRANT_CHECK_VERSION` changes. A party written as its ticker ("Blackstone to acquire PSB") resolves to the filer listing that ticker. `dropPrivateDuplicates` also matches the same buyer's private copy within 45 days by spacing-insensitive prefix, shared first word or the public record's ticker ("HILLROM" = Hill-Rom Holdings). Don't infer reversed roles from the buyer's filing index: bidders file SC TO-T and SC 13E3 under their own CIK too. They are often signed and closed at once, so a completion release can create one (status Closed). Enrichment (`enrichPrivateDeal`) takes sector / industry from the acquirer and marks Closed on the acquirer's 8-K Item 2.01; no premium, multiples, proxy, fairness or milestones. Premium and valuation medians therefore cover public targets only. The Deal Flow screener has a Public / Private target filter.
- **Three discovery channels** (all in `ingest/deals.ts`):
  1. Press releases (EX-99) found by full-text search (`QUERIES`) → `parse/press.ts`. A filer missing from today's directory (bought since: Chase Corp, Cowen) counts as listed if it was on an exchange then (`listedThen`, as in the backstop); otherwise its own release reads as a private target and a quoted premium drops it. Filings by a blank-check company are skipped (SPAC combinations): SIC 6770 on the hit and a SPAC-style name (`SPAC_FILER`: "Roth CH Acquisition V", "Forum Merger III", "Genesis Unicorn Capital Corp") or SPAC wording in the text ("trust account", "initial business combination"), since a de-SPACed operating company keeps SIC 6770 for years (Infrastructure and Energy Alternatives, bought by MasTec). A party described in prose ("Berry is a publicly traded …", "Rumble, the popular video-sharing platform") becomes the listed company or document filer whose name it starts with. All-stock deals need their own phrases ("representing a premium", "all-stock transaction" + "definitive agreement"): Capital One / Discover quoted no cash price, no "exchange ratio" and no "definitive merger agreement", and was missed until October 2026.
  2. Merger 8-Ks with Item 1.01 ("merge with and into the Company", tender offers) → `parse/eightk.ts`, which reads defined terms ("Parent", "Merger Sub", "Ultimate Parent") and names the sponsor behind a shell buyer.
  3. Backstop: every PREM14A / DEFM14A / SC 14D9 / SC 13E3 filer (each company on a joint proxy: AvalonBay *and* Equity Residential) without a deal announced in the 400 days before that proxy gets its 8-Ks from those 400 days re-parsed (`BACKSTOP_DAYS`; Terminix's proxy came 9 months after signing), up to eight, Item 1.01 8-Ks first (newest first), then communication-day ones (Piedmont filed six 8-Ks of deal news after its signing, which pushed the signing 8-K out of a plain newest-first six), press exhibit first, then the 8-K body; every candidate is read, so the same deal's earliest 8-K sets its date (Denbury's July 14 signing, not a July 31 amendment). A deal where the filer is the buyer counts only if its target is public (a joint proxy): its own purchase of a private business needs no vote, and hid Cowen's and Star Equity's sales. An older deal for the same company doesn't count, and each year's first proxy is looked up separately (`byYear`: Aerojet's failed 2020 deal with Lockheed, and its 2021 proxy, hid its 2022 deal with L3Harris). A record with a junk party name doesn't count either (tidy drops it), and a new parse replaces a junk buyer name ("Netherlands" → Just Eat Takeaway.com N.V.). The 8-Ks are those with Item 1.01, plus any filed on a day the company sent a DEFA14A / 425 / 14D-9C (GW Pharmaceuticals announced under Item 8.01; its first DEFA14A in the window was a 2020 annual-meeting supplement, so not just the first such day). Lookups are remembered per company and proxy year (`BACKSTOP_KEY`, "backstop3"); bump it to look every filer up again, and run `--backstop-only` from 2021 to apply a change to past years. The filer is taken as it was then: its name at the time (`nameOn`: Resolute Energy, not today's Cimarex Resolute), and listed then if `listedOn` says so (`FtsHit.listedCiks`; a company bought in 2019 has no ticker today, which used to drop its deal). A press release counts when it names the filer as the target, even by a short form (`namesCompany`: "Newfield", "EFI") or by a name it defines for the filer ("BTRS Holdings Inc. ("Billtrust")"), and never as the buyer (an acquirer's own vote).
- **Tickers:**
  - A ticker in a release resolves only if the company names agree, because tickers get reused after delistings. When a newer registrant reuses both the name and the ticker (SailPoint, bought in 2022, relisted in 2025 under a new CIK), the document's own filer of that name wins.
  - A bare all-caps target name ("WBD") counts as a ticker only when the same document lists it on an exchange ("(NASDAQ: WBD)").
  - Otherwise it is treated as an abbreviation and expanded from its definition ("Medical Manufacturing Technologies, LLC ("MMT")", `expandAbbreviation`).
- **Merging:** documents about the same target (by CIK) merge into one deal. Two announcements for the same target within 14 days are the same deal, unless both buyers are different listed companies (a rival bid: MKS and II-VI for Coherent, days apart). An update or completion joins the open deal with the same buyer; one naming another real buyer doesn't fold into a rival's open bid (II-VI's filings used to make MKS's losing bid "Closed"). A placeholder or shell buyer name ("Parent", "… Merger Sub", "… BidCo") is replaced by a real name from a later document. Only an announcement can create a deal; updates, completions and terminations modify existing deals. A document naming the buyer by its ticker is the same buyer (`isTickerOf`, in `applyParsed` and tidy): Two Harbors' earnings release ("UWMC") created a second UWM deal, and tidy then marked the real one topped by a rival. Private targets match within two years by `identicalNames` or `namesExtend` ("Rotron Aero" / "Rotron Aerospace Ltd."), or by the loose `sameCompany` only with the same buyer: on its own a shared first word joined Live Ventures' 2024 purchase of Central Steel Fabricators to Switch's 2021 one of Data Foundry, and requiring identical names split Darling's Gelnex and Ondas's Rotron into announcement and completion records.

- **Proxy enrichment:** a deal missing its premium or target advisors gets them from the target's DEFM14A / SC 14D9 / PREM14A (`parse/proxy.ts`), read once (`proxyCheckedAt`). It fills blanks only; it never overwrites a press-release value. `extractProxyPremium` reads "a premium of N% over / to / based on the closing price", "an N% premium over …", bullet lists ("a premium of approximately: • 125% over …", "a premium above X's stock price: • approximately 78% above …") and "(i) approximately 68% to …". Background words (proposals, "would", "submitted" …) are looked for in the premium's own list item, last 250 characters (a board's-reasons list runs on through its bullets: "… be submitted to the shareholders …: • the fact that …" lost Faro, Hanger, Activision); an unanchored premium (no announcement / last-trading-day reference) is checked over the whole item, and one after "$11.00 transaction consideration" is a bid (Kimball). The clause stops at ", and N%" / "(ii)", so a VWAP figure after it isn't this premium's. It skips the background narrative: named bidders ("Party A", "the March 28 Offer"), sentences opening with a date ("On October 16, 2025, …"), "would", "indicative", raised offers, ranges ("121% - 176%"), prices some time before signing ("one month prior"), VWAPs, averages and all-time highs; with no announcement / last-trading-day reference the sentence must name the merger agreement, consideration, exchange ratio or offer price. `premiumCandidates` lists every candidate with its score for debugging. October 2026: premiums read from 251 → 403 of 831 proxies; where a press value exists it agrees 248 / 270 times, and most disagreements were the old stored value being an earlier bid (Squarespace 39 → 15%, Sovos 57 → 27.6%). Checked with `.scratch/premium-regress.mts` (old vs new on every stored deal's proxy) and `.scratch/premium-fills.mts` (each new fill with its sentence). Wordings added later: "47 percent", "a premium of: • approximately 20.4% above …" (Veritiv), "(as) compared to" / "relative to" / "in excess of", "28% per share, based on", "closing prices" and "◾" bullets (423 of 793 proxies, agreement with stored premiums unchanged). The proxy also gives a stock or mixed deal's value per target share at announcement (`extractImpliedPerShare`: "the exchange ratio represented approximately $145.82 … for each share", "the value of the per share merger consideration … was $17.52", only for the last trading day before the announcement, never the latest practicable date); it fills a blank price, and the value then follows from the target's share count (NextEra / Dominion, II-VI / Coherent). It agreed with stored prices 23 / 27 times, and two of the four disagreements were stored prices that were only the cash part (Prudential, Vine). Computing a premium from the proxy's market-price table was tried and dropped: it agreed with stated premiums 18 / 32 times (rumour dates, the latest practicable date, the other company's stock). Bump `PROXY_PARSER_VERSION` when the reader changes: deals still missing a premium, a target adviser or a stock deal's price are read again (`proxyWanted`).
- **Premium means premium over the unaffected / last closing price.** Premiums over VWAPs, 52-week highs, earlier proposals or precedent medians are ignored. If only those are stated, the premium stays `null`.
- **Status comes from the target's filing history:** PREM14A / DEFM14A / SC 14D9 / SC TO-T / S-4 → Pending; Form 25 / 15 or an 8-K Item 5.01 → Closed; an 8-K Item 1.02 that mentions terminating the merger agreement → Terminated. Whichever came first wins: a termination before the delisting ends the deal (JetBlue / Spirit, terminated March 2024; Spirit's Form 25 in 2026 after its bankruptcy closed nothing). A termination counts only if it is over 30 days before the closing filing (credit agreements are ended "in connection with the Merger" at the closing), no merger proxy or tender follows it (CP / Kansas City Southern ended in May 2021, was signed again and closed), and the 8-K says the merger agreement itself was terminated (`saysMergerTerminated`: not a right to terminate, not "if the Merger Agreement is terminated", nothing after the forward-looking-statements boilerplate). Closed deals stored before `STATUS_RULE_VERSION` are re-checked once (`statusRule`). A company that keeps reporting after it is bought (bonds or preferred shares: Athene, Continental Resources, STORE Capital, Triton, Domtar) is Closed when the filings agree (`isClosingFiling`): one 8-K reports the completion and the change of control (Items 2.01 and 5.01, also Bally's, which stayed listed), or the common stock's Form 25 comes within five days of an 8-K reporting either; a Form 25 with an 8-K Item 3.01 only is one preferred series (II-VI). A terminated deal came back only if the target then files a new merger proxy or tender document (`REVIVAL_FORMS`, originals): an amendment reports the end (Battalion's last SC 13E3/A), and an S-4 is another deal (HomeStreet's with Mechanics Bank). A private deal is Terminated when the buyer's 8-K Item 1.02 says the merger agreement ended and names the target (`privateTermination`, each 8-K read once per deal: `term:` keys in `seen`; Adobe / Figma, Verisk / AccuLynx). A target found only by name in today's listed-company file must have been reporting then (`provablyUnlistedOn`: no 10-K / 10-Q in the year before, judged only when the filing index reaches back that far); stored open records whose target listed later become private deals, or are dropped without a listed buyer (Figma and BitGo listed in 2025, years after Adobe's and Galaxy's agreements). October 12 2026: open records over 18 months old went from 41 to 18; An open record over four months old whose "target" filed no target's document (merger proxy, 14D-9, 13E-3) but registered shares or launched a tender (S-4, F-4, SC TO-T), while the "buyer" filed the target's documents, was read backwards: the roles are swapped, or the record dropped when the deal is already tracked (`reverseRoles`: Novartis "bought" by MorphoSys, EchoStar by DISH). A foreign target files 6-Ks, never an 8-K Item 1.02, so the buyer's 8-K reports the end (Intel / Tower). most of the rest are read backwards (MorphoSys "buying" Novartis) or foreign targets that file 6-Ks.

Defined terms, clauses ("Parent that was formed solely …"), descriptions ("…, one of the world's leading …") and the vehicle itself are rejected. The sponsor is linked to a company record only if it trades on a US exchange (Oracle, Apollo; not the OTC "Authentic Holdings, Inc."). A shell buying the buyer of another deal is then dropped by tidy (Oracle's "OC Acquisition"). October 2026: 33 of 50 vehicles named (Squarespace → Permira, Dun & Bradstreet → Clearlake, Billtrust → EQT).

Recipients compare without spaces ("ExxonMobil" = Exxon Mobil Corporation). October 2026: 88 deals gained a buyer's bank (Microsoft / Nuance → Goldman Sachs). - **Values from the announcement release:** a public deal with no value (often an all-stock deal rebuilt from its merger 8-K, which states a ratio, not dollars) is looked up once (`valueCheck`, `VALUE_CHECK_VERSION`): the target's and the buyer's 8-K exhibits and 425 / DEFA14A filings from five days before to three after the announcement (`announcementTerms`). A release counts when both companies are named near the top (a shell buyer no release names is skipped), it reads as a signed agreement and not a completion or termination (`releaseTerms`); it fills the value, premium and consideration, never the price per share (a release's first "$ per share" can be the unaffected price). An amount followed by "of … synergies", "in … transaction / integration costs", "in value creation" or "in January 2027" (a later instalment) is not a price either (II-VI's "$200 million of run-rate cost synergies"; Aon / NFP's "~$400 million in expected one-time transaction and integration costs"), and the lead ("value of") never reaches across a bullet. Combined-company figures are not deal values: an amount whose own sentence says the deal is creating / forming something, or calls it combined / resulting, is skipped ("creating a premier … business, with an initial enterprise value over $35 billion": EQT / Equitrans), and slide decks, call transcripts, FAQs, memos and reprinted articles filed as 425s are not read (`looksLikePressRelease`; "Merger Creates … >$35 B Enterprise Value ~$23 B Equity Value"). Up to ten filings a day are read (Webster filed a dozen 425s on announcement day). Mergers of equals usually state only the combined company's size and stay blank. First, a date taken from a later 8-K (an amendment) moves back to the target's earlier signing 8-K naming the same buyer (`earlierSigning`). Exxon / Pioneer → $59.5B, Santander / Webster → $12.3B, Amgen / Horizon → $28.3B EV.
- **Names at announcement:** a target's name is the one it had when the deal was announced (`nameOn` reads EDGAR `formerNames`: "FLIR Systems", not "Teledyne FLIR"). When acquirer and target still look identical (`identicalNames`), the acquirer's old name is used too ("Southern California Bancorp"); a buyer that was a SPAC then is dropped, and an exact same name on both sides is dropped.
- **EV and multiples:** none for banks, insurers, brokers (SIC 6000–6499) or mortgage REITs (6798 with a lending name): deposits and repo funding aren't debt. An implied equity value (price × shares) is ignored when the share count is under 500k or the result is more than 2× off the stated value (a reverse split since the last filing). Revenue takes the largest of the revenue tags reported for the latest period (`series(..., largest)`): a REIT tags only fee income as "RevenueFromContractWithCustomer…", which gave Monmouth 57× EV/Revenue. EBITDA = operating income + D&A (`ebitdaOf`): operating income, else pre-tax income plus interest expense (ChampionX stopped tagging operating income in 2018); D&A as one figure, else depreciation plus intangibles amortization (Perficient), the latter left out only when the company reports none. Every figure must come from a fiscal year or balance sheet in the 15 months before the deal (`ltm(rows, asOf)`, `latestInstant(…, asOf)`): stale tags had given ChampionX a 2017 EBITDA, Verso its pre-2016 debt and Leggett & Platt a 2020 debt figure. Convertible and senior notes count as debt when there is no debt total (Mandiant). A company whose debt can't be read but whose interest expense is over 0.5% of the equity value has no EV unless the deal states one (AES tags its debt with its own tags: equity minus cash made it 3x EBITDA). Bump `FINANCIALS_VERSION` to recompute every deal's multiples (`financialsVersion`). October 2026 sample: EV/EBITDA on 113 → 128 of 298 deals, EVs corrected (QAD, Berry Global, Mandiant, Verso).
- **HTML entities:** `decodeEntities` (`ingest/text.ts`) knows the Latin-1 accented letters by name ("&auml;" → "ä"); names like "BillerudKorsnäs" were cut at the undecoded entity before. They used to decode to invisible control characters, which hid every defined term ("the Company", "Parent") from the 8-K parser; fixing that (October 2026) roughly doubled the 2019 history's coverage.
- **Press-release headlines** (`splitHeadline` in `parse/press.ts`): the first line naming the deal wins over the block just above the dateline, which is often sub-headlines ("Merger delivers…", "Combined Company…"). It takes the line above when the deal line can't start a headline ("… Enters into a Definitive" / "Agreement to be Acquired by …"), and the lines below only where the headline wraps (lower-case start, a line ending "to Acquire" / "to be", both in capitals), never a sub-headline ("… to Acquire Tableau" / "World's #1 CRM"). A deal announced with results reads "<Company> Announces agreement to be acquired …". Contact lines (phone, e-mail, PR firms) and labels ("FOR IMMEDIATE RELEASE …") are skipped. A possessive is a carve-out only before a business word ("Honeywell's valve unit"); otherwise it belongs to the name ("Mama Mary's Pizza Crusts", "Papa Murphy's"). "assets from <the named company>" in the opening text is an asset purchase ("Hess Midstream … to acquire DJ Basin … storage assets from Chevron" made Chevron a target; Synacor / Zimbra, Discover / SLC); a possessive in the text is not ("LHC Group's outstanding common stock"). "Previously announced" in the first paragraph makes an update only when the headline doesn't announce the deal itself. One deal adjective may stand before "acquisition of" (`DEAL_ADJ`: transformative, strategic, accretive …; not "proposed", often a hostile bid): "EQT Announces Transformative Acquisition of Equitrans Midstream" read as nothing, and every rebuild lost the deal. A name followed, right after the verb, by an asset word or a comma list ending in one is a carve-out ("… of Producing Properties in the Gulf", "… of South32's Bauxite, Alumina, and Aluminum Assets"; not "Rouse Properties Reports …"). Headline tail words end a name in capitals too ("CORNERSTONE BANK ACQUISITION ADDS …"). Checked with `.scratch/parse-regress.mts`, which re-parses the history's sources with the old and new code (2,274 releases: 4 lost, 6 gained, ~75 names corrected).
- **8-K defined terms:** "the Partnership", "the Registrant" and "the Trust" mean the filer, like "the Company" (`SELF` in `parse/eightk.ts`). "Eli Lilly and Company" stays one name (the clause-word stripping no longer cuts at its "and"). "a subsidiary of Parent" is not a sponsor. Legal documents ("Restated Credit Agreement", "…Indenture…") and month-year dates are not names (`isPlausibleName`), nor document headings ("Definitive Proxy Statement on Schedule 14A", "Transaction Details F5"), and business development companies are not targets (`junkReason`: "BDC" in the name, or a no-industry "… Investment / Capital / Finance / Credit Corp"). Ltd"; `cleanPartyName` cuts ", a Delaware limited partnership". A bare legal suffix ("Corp" cut from "Corp Merger Sub") is not a name: it once resolved to International Bancshares Corp. "The Company will merge with and into Corp Merger Sub" makes the Company the target (Callodine / Manning & Napier). A private company bought by a SPAC is dropped (`junkReason`: industry "Blank Checks" from the buyer's SIC 6770 *and* a SPAC-like buyer name, since a de-SPACed operating company such as IEA can keep SIC 6770 for years). The usual terms count without quote marks too (`(the Company)`, `(Parent)`, `(Merger Sub)`, `(the Company or Icosavax)`): Equitrans's signing 8-K printed none, which hid its deal from the 8-K channel and the backstop; a description never runs on across another party's definition. "AstraZeneca Finance and Holdings Inc." stays one name, like "and Company". Defined holders ("the Tenax Members") are not parties, "Tenax at the Closing" is not a name, and `cleanPartyName` cuts a plural headline verb ("SD Biosensor and SJL Partners Complete Transaction").
- **8-K deal structures** (`parse/eightk.ts`, from the October 2026 big-deal check): "Item 1.01 - Entry…" headings; a defined term between the verb and its object ("Merger Sub will merge (the "Merger") with and into the Company": Pioneer, Billtrust); UK / Irish schemes of arrangement under a "Transaction Agreement" ("Acquirer Sub will acquire the Company", "the Purchaser will acquire the issued … share capital of the Company": Horizon, Nielsen) and two-step deals ("Banco Santander will acquire Webster"); "entitled to receive $116.50"; a listing between a name and its description ("Magellan Midstream Partners, L.P. (NYSE: MMP), a Delaware limited partnership") is removed first. The object of "with and into" and the subject before "will merge" are the defined parties written there, longest first ("Mr. Cooper", not "Mr"); a named party written after the last merger-sub mention is the one merging (Sterling into Webster; AvalonBay into Equity Residential's merger sub, which makes Equity Residential the buyer, not the sub). With several mergers (an OpCo first), the one into the filer wins (Radius). "will, subject to the terms and conditions …, merge with and into" counts (FB Financial / Southern States: the holding companies' merger, not the bank merger after it); a merger-sub sentence read only through such a clause yields to a plainly worded one, and when all are clause-split the last wins (a new holdco buying both sides: Media General / LIN, Delek / Alon). "… Acquisitions Inc." is a vehicle name (Pageflex). "would merge with and into" counts like "will" (First Financial / Finward). "the First Surviving Company will merge with and into Merger Sub II" is the second step of a two-step merger and is ignored (it made Diamondback the target of its purchase of Endeavor). An amendment ("First Amendment to Agreement and Plan of Merger", or "As previously announced, …" at the top with no signing date) is an update; "As previously announced, on April 26, 2021, … entered into an Agreement and Plan of Merger" is the signing 8-K itself, filed days after the press release (Grace, Raven, Intersect ENT), and stays an announcement unless filed over 10 days after that date (the signing 8-K is due within four business days; ZeroFox's note-repurchase 8-K 29 days on made its lender a buyer) (`signedOn`, checked in `applyParsed`: Genworth's extension 8-Ks restate a 2016 signing). An update fills gaps in the existing deal and never creates one (Vista Outdoor's amendment listed Revelyst first and made a second deal with Revelyst as the buyer). A second defined term counts ("Mr. Cooper" or the "Company"); an earlier party's term in front of a name is dropped ("by and among Perry Ellis, Feldenkreis Holdings LLC"). Buyers described as "newly-formed entities … led by funds affiliated with Elliott …" or "the acquisition of the Company by affiliates of Stone Point …" are named by that sponsor, never by a defined term ("Parent in an all cash transaction"). Jurisdictions ("Florida", "Nevada corporation", "Luxembourg") and defined agreements ("Closing", "Amendment", "… Agreement") are not names (`isPlausibleName`). "Business Combination Agreements" stay out (de-SPACs).
- **Deal values from text** (`extractValue`): not a firm's track record (a count of deals nearby: "376 transactions completed, valued at $212 billion", "80 investments … 200 add-on acquisitions … with a total value of approximately $50 billion", "since 1988"), not a year's activity ("$212 billion in the year ended March 31, 2020", only right after the amount: a year-end in the sentence before is fine, Asbury / Herb Chambers $1.45B), not a face value (Encore's purchased debt "face value of over $130 billion", convertible notes) and not another dollar (C$, A$, NT$, HK$, S$, R$, MX$: Exar / iML's "NT$6.8 billion" was read as US$6.8B; Evertec / Dimensa's R$950M). The 2010–2020 history had these as its largest values. A price × shares value needs a share count of at most 15 billion (an XBRL count tagged a thousand times too big made Sun Healthcare's $215M sale $215B) and, without a stated value, must stay under $100B.
- **Offer price** (`extractPrice`): not a buyback in the target's earnings release ("repurchased … at an average price of $23.04 per share" was Beazer's offer; it was $33.50), not a share price quoted for reference ("based on Herman Miller's five-day volume weighted average price of $43.94"; the implied $25.06 is the offer), not a collar bound on the buyer's price ("no less than $23.12 per share"; a floor in the offer itself, "Sentio stockholders will receive … no less than $14.37", counts) and not a top-up ("an additional $0.55"). "acquired by Dream Finders Homes, Inc. for $33.50" reads past the abbreviation. Checked on 63,982 cached releases: ~60 prices corrected (bank deals now give the implied value per target share, not the buyer's price), ~70 dropped (all reference prices or bounds).
- **Consideration (cash / stock / mixed)** is decided by the sentence saying what holders "will receive" first, then the whole text: a cash-or-stock election is mixed ("Stock Election" / "Cash Election": Penumbra), an exchange ratio may stand before legal words ("3.8721 fully paid and non-assessable Parent Shares"), warrants per share are not shares, and "£4.39 ($7.06) in cash" is cash (in the offer sentence only; "$2.4 billion in cash" elsewhere is the balance sheet). That pass moved 110 releases from Cash to Mixed (QLogic, Office Depot, Questcor …). Earlier rules: financing talk ("funded with cash and new shares") made HPE / Juniper look mixed, and "one Union Pacific common share and $88.82 in cash" now reads as mixed. A share count in capitals counts ("one ListCo Share and $5.00 in cash"), and the 8-K price ignores cash paid on top of shares (WestRock read as a $5.00, $1.3B deal). Stored deals pick this up on a rebuild.
- **Activist investor names:** EDGAR lists people surname-first ("ICAHN CARL C"), but filer-typed names come in either order. `individualName` (`parse/thirteend.ts`) applies only to reporting persons the 13D marks as individuals ("IN"): the person's own signature decides ("/s/ Carl C. Icahn"), else an all-capitals EDGAR name is turned around, else the name is left as filed. Stakes under 1% are shown as unknown (a 13D means 5%+). Stored stakes were fixed once (`13dname:` markers in seen docs). `displayName` uses the shared `titleCaseCaps`, so "FUND II LP" stays "Fund II LP"; `displayCompanyName` also repairs "Lp" / "Ii" in stored names.
- **The month in progress** is shown, not hidden: `monthlyVolume` ends with the data's own month so far, and `VolumeMatrix.partial` marks it. Charts draw it lighter with a "*" label, "to date" in the tooltip and a footer note (`partialIndex` on `LineChart`). Month-on-month changes, the monthly average and "Latest month" use complete months (`completeMonths`); the Volume page shows "Oct to date" instead of the latest month while one is in progress. Year to date (`HubData.yearToDate`, `yearToDate()` in `lib/aggregate.ts`) runs through the data's day and is compared with the same days a year earlier (Jan 1 – Oct 7 vs Jan 1 – Oct 7), so a partial month never reads as a slump.
- **Volume chart range** starts at `coverageStart` (the first month with at least a quarter of a typical month's deals), not at the earliest deal: a few 2020 deals found when they closed made late 2020 look like a collapse.
- **Data quality:**
  - `ingest/tidy.ts` runs after every deal ingest (no requests, so it also repairs old records). It removes implausible names, self-deals and private "targets" that are merger vehicles (`isMergerVehicle`: "… MergerCo", "… Merger Sub"; Holdco / Topco names are real entities, and a registrant's SEC name is never a placeholder), re-cleans names that have no CIK, clears premiums outside −50%…300% and values under $1M, re-checks fees against the final value (`saneFee`: 0.3–10% target, 0.3–12% reverse), keeps a bank on the target side only, merges the same buyer's second record within 60 days ("H&F" = "Hellman & Friedman", `SHORT_FORMS` in `parse/names.ts`), and marks an agreement Terminated when a rival buyer signs with the same listed target within 120 days (Optum over Option Care for Amedisys), drops the copy of a deal read with buyer and target swapped (keeping the record whose target filed the merger proxy or tender response: First Financial / Finward), or later while it is still open or "Closed" only by the winner's closing filings (Lockheed / Aerojet 2020, superseded by L3Harris in 2022; status date left blank).
  - Two open records for the same listed target announced the same day are merged, keeping the better-documented record and its buyer (Heska: Mars, and Antech from Heska's earnings release; Ikonics: TeraWulf over "Company entity"). A buyer named "New <target>" ("New R1") is a holding-company reorganization, like "… HoldCo". A swapped copy is also recognized when its buyer has no CIK, by name (Whiting "buying" its own buyer Oasis). A → B is dropped when B → C and A → C were announced within 30 days: rival bids read as a deal between the bidders (MKS and Lumentum "buying" II-VI during the Coherent contest). A national bank subsidiary (", N.A.") is a lender, not a buyer (Citibank and Synnex).
  - A private "target" named only for an oil and gas basin (`BASIN_NAME`: "Eagle Ford", "Permian Basin", "Bakken" …) is an asset purchase (Crescent Energy buying Devon's Eagle Ford assets): never created, and dropped by tidy. A description ending "Company" with "enabled / focused / driven" ("Technology Enabled Health Assessment Company") is not a name either; a longer description before a name goes too ("U.K. Firefighter Turnout Gear Manufacturer Bristol Uniforms", "Specialist M&A Advisor Portico Capital Advisors", "Existing Strategic Partner Adlumin", "Marks Paneth LLP NYC Accounting Firm"), but not from a name ending in the role word ("Hunter Fan Company", "Browser Company of New York") or before a bare acronym ("Carlisle Management Company SCA"), nor a run of hyphenated words ("Cash-Flow-Positive"). The same buyer's private purchase recorded twice within a year under identical or word-by-word shortened names is merged (announcement and completion: Gelnex, Rotron, Choice / Radisson Hotels Americas), and a private purchase by an "… Acquisition Corp." is a de-SPAC whatever its industry code says now (Rice Acquisition / Aria Energy).
  - A description in front of a one-word name goes ("Brazilian Collagen Producer Gelnex" → "Gelnex", `cleanPartyName`); a headline cut after one ("… Acquisition of Mobile Game Creator") takes the name that runs on in the text ("Playdemic from AT&T"), never a dateline ("CLEVELAND, Ohio") or a sentence start. "Pacific Premier Bancorp" and "e.l.f. Beauty" stay whole ("Premier" starts a description only after "a").
  - Removed records are deleted from Supabase on save (`State.dropped`); a plain upsert would keep them.
  - `npm run audit` checks every rule in `audit-rules.ts`. The October 2026 pass took flagged records from 5.1% to 1.7%. What remains is mostly legitimate or known: EV far above equity for heavily indebted targets (Sotherly, Hall of Fame Resort), placeholder buyers no filing names, and multiples stored before the bank / share-count rules (recomputed by a rebuild). Veoneer is a known miss: EDGAR's name lookup doesn't know it.
- **Parser changes need a test** in `ingest/parse/*.test.ts`. Fixtures are synthetic text in the style of real filings.
- **EDGAR etiquette:** always go through `ingest/edgar.ts`, which sends the User-Agent and throttles to ~8 requests/second.

## History foundation (for the what-if engine)

Separate from the live features: its own tables (`supabase/migrations/0002_history.sql`), its own CLI (`npm run history -- <command>`, `ingest/history.ts`) and local files (`.data/history/`). The live tables and pipelines are unchanged; the only reader on the site is the what-if screen (`sector_monthly`, through `/api/what-if`).

- **`deals_history`**: deals announced 2010–2020 (2010–2014 added in October 2026; `HISTORY_FROM` in `ingest/history.ts` is the start of every history table), found by the live discovery channels and parsers (`npm run history -- deals --from … --to …`, `ingestDeals(..., { light: true })`). Light enrichment skips fairness opinions and deal protections (gigabytes of proxies); status, sector, names, premium, advisers, milestones and multiples are filled. 2021 onward lives in `deals`; `mergeDeals` combines both without double counting (same id, or same target CIK within 30 days: the live record wins).
- **`ipo_history`**: priced IPOs since 2010 (2,297) from 424B4 final prospectuses (`ingest/ipoHistory.ts`), with the live pipeline's IPO tests (no earlier periodic report or 424B4, an S-1 / F-1 on file, not a SPAC, fund, resale, direct listing or de-SPAC). Pricing date = the prospectus cover date ("The date of this prospectus is …") when within ten days of the filing, else the filing date. Raise = offer price × cover shares (base deal, no over-allotment). `filingsUntil` reads a company's older submission pages, since `filings.recent` holds only ~1,000 filings.
- **`sector_monthly`** (one row per sector per month, 2010-01 to the last complete month; `lib/history.ts`):
  - **ETF:** XLK = Tech, XLV = Healthcare, XLE = Energy, XLF = Financials, XLI = Industrials. Month-end close, plus the total return from Yahoo's dividend-adjusted close (Stooq now returns 403; other free APIs need keys).
  - **Deals:** counted like the volume chart (terminated excluded). `deal_value_usd` sums **one** value type (default `transaction`, the headline value; `--value-kind equity|enterprise`) in today's dollars (CPI-U, latest published month; October 2025 CPI was never published and is interpolated). Deals left out are counted: `deal_value_null_n` (no value), `deal_value_other_kind_n` (another type).
  - **IPOs:** `ipo_count` = IPOs priced that month (from `ipo_history`).
- **`macro_monthly`**: FRED monthly averages (public CSV, no key): FEDFUNDS, GS10, VIXCLS, CPIAUCSL, and two credit spreads. ICE BofA HY OAS (BAMLH0A0HYM2) is limited on FRED to ~3 years by ICE's licence, so Moody's Baa − 10-year (BAA10Y) is kept as the full-history spread. The local file also carries the WTI oil price (DCOILWTICO, `oilUsd`) and the biotech ETF (XBI month-end adjusted close, `biotech`; `INDEX_ETFS` in `ingest/markets.ts`); they aren't Supabase columns. Tried as engine inputs in October 2026 and left out (no gain; `EXTRA_INPUTS` in `research/estimate_links.py`, research/experiments.md).
- **`snapshots`**: on the 2nd of each month `.github/workflows/history.yml` runs `npm run history -- monthly`. It refreshes markets, adds the last two months' IPOs and rebuilds both monthly tables. It also saves the IPO pipeline as shown and the YTD league table at month end (`kind` = `ipo_pipeline` / `league_table`, `period` = the month just ended), plus the raw market series (`markets` / `latest`) as a fallback when a source fails.
- **`valueKind`** stays in stored records and the server-side read (`DEAL_FIELDS` in `lib/data.ts`, optional `Deal.valueKind`); `toPublicDeal` still leaves it out of the browser feed (tested).
- **Coverage check:** `recall` counts, per year and per sector (filer SIC), the merger-proxy / tender filers and how many have a deal. `report` turns that into weak years and sector-years with `coverageFlags` (`lib/history.ts`, tested) and writes `.data/history/coverage_flags.json` for the estimator. 2021 to last year is the reference and never weak. A year is weak under 70% of the reference's public-target deals or 80% of its recall. A sector-year is weak when its year is, or its recall falls under 80% of the sector's reference (needs 5+ filers; else under 50% of the sector's deals). Every calendar year is listed, so a year with no deals shows up as weak. After the October 13 re-read (5,465 history deals, 4,840 before): 2010 is weak (recall 47% vs a 62% reference) and 2020 (122 public-target deals vs a reference of 179, the COVID year); 2011–2019 are sound (51–64%); weak sector-years: Energy 2011, 2013, 2016 and Financials 2011–2014, 2019. That re-read also found megadeals the history lacked (Cigna / Express Scripts, Bayer / Monsanto, AbbVie / Allergan) and dropped inflated values (a $215M sale read as $215B); one reversed holdco record remains ("Covidien → Medtronic Inc", $34.5B, November 2014).
- **Order of work for a fresh history:** `deals` (hours) → `ipos` → `markets` → `recall` (per-year coverage against merger-proxy filers) → `report` (builds the tables locally) → `push` (after the migration) → `npm run estimate`. Never run two EDGAR-heavy commands at once: each process throttles itself to ~8 requests a second, and SEC's limit is 10.

## Ripple engine (what-if)

Pure functions in `lib/ripple/`, separate from the existing features; only the what-if screen uses them. Try it with `npm run ripple -- --shock …` (`--links hand-set` to compare).

- **Variables:** 20 = 4 features (valuation = sector ETF, deal count, deal value, IPO count) × 5 sectors, each a % deviation from what would have happened without the shock. Macro inputs (Fed funds, 10-year, Baa spread, VIX) can be shocked in natural units (pp; VIX points) but get no feedback.
- **Two link sets**, picked by `LINK_SET` in `settings.ts` (default `"estimated"`):
  - **Hand-set** (`links.ts`): 12 feature, 11 sector and 15 macro links, each with a direction, strength, lag, one-sentence reason and `status: "assumption — not yet estimated from data"` (a test enforces this). They are also the priors of the estimation.
    - Feature links C (lags 0, 1, 2 → C0, C1, C2) are elasticities: strong 1.0, moderate 0.5, weak 0.2.
    - Sector links L: each sector reaches itself with 1; the share reaching another sector is strong 0.5, moderate 0.25, weak 0.1.
    - Macro links M are % per unit (+1 pp, or +10 VIX points): strong 10, moderate 5, weak 2.
  - **Estimated** (`estimated.ts` from `estimated.json`, see "Link estimation"): the same links and reasons with an estimated `value`, 90% `range`, `n`, data `weight` and `prior`. Direction and strength follow the estimate. `status` becomes `"estimated from data"` only at data weight ≥ 0.5; a link still mostly prior stays an assumption. A macro effect found sector-specific becomes one link per sector. A hand-set macro link the data puts at zero (no separate sector effect) is left out.
- **Engine** (`engine.ts`): `A_lag = C_lag ⊗ L` (feature-major index = feature·5 + sector) with self-links zeroed, so a variable's own shock just fades. Shocks hit in quarter 1. A lag-ℓ link fires ℓ quarters later and fades from then on: `y_k = λ^(k−1)·s + Σ_ℓ<k λ^(k−1−ℓ)·(A_ℓ·s + M_ℓ·m)` (one round).
  - λ can be one number or one per feature (`fadeOf`): the fade of the feature an impulse lands on. The backtest picked valuations and deal counts 1 (persist), deal values 0.85, IPO counts 0.7 (`tuned.json`).
  - `rounds: 1` = direct effects only; 2 (or 3, `MAX_ROUNDS`) adds effects of effects, and `explain()` then shows the variables a chain passed through (`via`). The backtest picked 3.
  - Range: a link with an estimated `value` and `range` uses those; otherwise its contribution is taken at ±50% (positive and negative contributions bounded separately).
  - `QuarterResult.assumed[sector][feature]`: the share of each result's knock-on effect that travels through at least one assumption link. The screen badges a result above `ASSUMED_ABOVE` (0.5). `RippleResult.handSet` = any link in use is an assumption.
  - `explain()` lists a result's contributions with the link entries behind each hop (and `assumed`).
- **Settings** (`settings.ts`, the single place): link set, fade, range, horizon, rounds, adviser window, presets and slider ranges. Fade and rounds come from `tuned.json`, written by `npm run backtest` with the setup that forecast best; for a link set the backtest didn't pick they fall back to v1 (0.7, 1 round). The screen reads everything from here.
- **Advisers** (`advisers.ts`): each bank's share of sector deal value over the last 3 years (league-table credit, both sides) × the sector's average quarterly deal value × the predicted % change, summed over the quarters. Banks are ranked by predicted change, with range, % of baseline and driving sector.
- **Levels** (`baseline.ts`): turns % responses into quarterly levels using the last four complete quarters of `sector_monthly`.

## Link estimation (`npm run estimate`)

`research/estimate_links.py` (Python 3, statsmodels; `python -m pip install -r research/requirements.txt`) estimates every link from the local history and writes `lib/ripple/estimated.json` (committed) and `research/link-estimates.md` (the hand-set vs estimated report, regenerated each run). `npm run estimate` first exports the hand-set links (`npm run ripple -- --export-handset`). Inputs: `.data/history/` (`npm run history -- report`) and BEA's `AllTablesIO.zip`, unzipped into `.data/bea/io/` (git-ignored, from apps.bea.gov/industry/iTables Static Files/).

- **Panel:** quarterly, 5 sectors. Valuation = sector ETF log total return. Counts and values enter as log changes of log(x + c) (c = 1 for counts, $100M for values), winsorised at 2.5 / 97.5%. Weak sector-years (coverage check) are blanked: left out where a deal figure is the target, and counted as "no change" plus a missing-data flag where it is an input, so those quarters' ETF and macro data still count. IPO links stay at their prior until the IPO history is in (the same 12-month test as `ipoHistoryReady`).
- **C and M:** one statsmodels OLS per target feature with sector fixed effects. Regressors: the other features at lags 0–2, the target's own lags 1–2 (controls) and the four macro changes at lags 0–2 (VIX per 10 points). A macro effect gets sector-specific coefficients only when an F-test rejects a common one (p < 0.05). Lag-0 links are same-quarter associations, not causal.
- **L:** half BEA input-output (share of sector i's output driven by sector j's final demand; Leontief total requirements on the 71-industry use tables 2015–2023, mapped like `sectorForSic`, with pharma split out of chemicals and medical devices out of misc. manufacturing by 2017 detail shares). Half the ETFs' co-movement: the slope of i's residual on j's, after the other three sectors' average return (an ex-pair market; SPY would put Tech, ~30% of it, in its own benchmark and fake negative spillovers) and the four macro changes.
- **Shrinkage:** a normal prior on every coefficient, centred on its hand-set value (0 without a link), sd half its size (floors 0.1 / 0.05 / 1 for feature / sector / macro; 0.2 / 0.1 / 1 around zero), times `PRIOR_SCALE`: the prior width the backtest picked, per link kind (`f0.25/s0.5/m0.5`: feature links ×0.25, sector spillovers ×0.5, macro ×0.5; read from `backtest.json`). Posterior mean = ridge toward the prior. Data weight = 1 − posterior variance / prior variance, so tighter priors leave fewer links "estimated" (7 of 38 with the October 13 history). `ESTIMATE_FROM` (`--est-from`) can start the estimation later; 2010, 2012, 2013 and 2015 starts all backtest within noise of each other: forecasts improve when estimates stay close to the economic reasoning.
- **Ranges:** 1,000 bootstrap runs resampling whole quarters (and an IO year), each adding the prior's remaining uncertainty, (1 − weight) × prior sd; 90% = 5th–95th percentile.
- **Report verdicts:** agreed (hand-set inside the range), stronger / weaker, flipped (opposite sign, range excludes 0), too weak to matter (under a quarter of the weakest strength, range includes 0), plus links still mostly prior. It also lists links the data suggests that the engine doesn't have (not added: each needs a reason first).
- Not estimable: valuation → valuation (lag 0) is cross-sector co-movement and stays hand-set. Deal growth is noisy (quarterly swings of ±100%+), so most links into deal counts and values stay mostly prior.

## Backtest (`npm run backtest`)

`research/backtest.py` re-estimates the links at every quarter from 2019Q1 using only what was known then (quarters before it, ETF months before it, IO tables up to the year before), for prior widths ×0.25 / 0.5 / 0.75 / 1 / 2 and 11 per-kind combinations (`f…/s…/m…`: feature / sector / macro links), into `.data/history/backtest_input.json` (about 1.5 minutes). `ingest/backtest.ts` then scores the real engine (`lib/ripple/backtest.ts`, tested):

- **Inputs at each quarter t:** the four macro changes and each sector's ETF move versus its trend, less the part the engine already puts down to the macro changes (else they'd count twice). The engine predicts t … t+3.
- **Earlier shocks (`history`, `BacktestOptions` in `lib/ripple/backtest.ts`):** the same inputs for t−1 and t−2 are run through the engine too, and the part of their ripple still to come counts: level at t+k−1 less the baseline the outcome is measured from (the quarter before t for valuations, the average of the four before for flows). Their effects are still travelling through the lagged links at the forecast date, so ignoring them threw away information the model itself implies. Searched over 0–2 (the engine's longest lag); 3–6 only fitted 2019–2020. Deal and IPO numbers are never inputs (feeding past deal / IPO surprises was tried and hurt: they're mostly noise). The scenario screen runs one scenario and has no history; only the tuned fades it uses changed.
- **Outcomes:** valuations against the quarter before (prices ≈ random walk); deal and IPO counts / values against the average of the four quarters before, plus trend (one odd quarter doesn't set the yardstick), less the calendar pattern (`seasonality`: deals dip ~21% in Q1, IPOs bunch ~43% in Q2; pooled over sectors, from earlier quarters only). The same quarter's valuation is the input and isn't scored. The scored panel is fixed (total deal values, standard clipping) whatever the estimation variant, and starts in 2015 (`SCORE_FROM` in `research/backtest.py`), so trends and the calendar pattern are measured as before the history went back to 2010 and results stay comparable.
- **Metrics:** skill = 1 − SSE / SSE of "no change from trend"; direction = right sign for predictions ≥ 0.5 points; slope = realised on predicted (1 = sized right).
- **Search:** history 0–2 × hand-set vs estimated (each prior width) × 1–3 rounds × a fade per feature from {0.4, 0.55, 0.7, 0.85, 1} (separable: a feature's prediction depends only on its own fade). Score = average skill over the four features (per-horizon skills averaged, so long noisy horizons don't dominate). Both halves of the period are reported to check the choice holds.
- **Result (October 13 2026, re-read history from 2010, earlier shocks):** estimated links, priors ×0.25 feature / ×0.5 spillover / ×0.5 macro, 3 rounds, fade 1 / 1 / 0.85 / 0.7, the last two quarters' shocks. **Direction right 64%** (61% with this quarter's shocks only; valuations ~71%, deal counts 65–68% from two quarters out, deal values 52–60%, IPOs ~64%); skill 0.158 (0.086 untuned), and better than untuned in both halves (0.210 vs 0.102; 0.096 vs 0.061). The earlier history (October 7: priors ×1 spillover, fade 1 / 0.85 / 0.85 / 0.55) gave 0.149 and a recent half of 0.080. With the history from 2015 it was 65% and 0.164, but the later half only matched the untuned engine (0.056 vs 0.059); on today's data every estimation start lands at 64.3–65.0%, so the extra years didn't move direction but made the recent-half skill hold. Weak spots: Healthcare and Energy deal counts (~50%: their deal activity doesn't follow the sector's prices; per-sector links were tried and the data can't support them, t < 1).
- **Experiments** (`research/experiments.md`, hand-written log): eight further ideas were tested on the same yardstick and rejected (magnitude calibration failed cross-validation; per-kind prior widths, quarter-of-year controls, capped deal values, stronger clipping, data-suggested spillovers, end-of-quarter macro, excluding 2020 all ≤ the current skill). The switches stay in `research/estimate_links.py` (`SEASONAL`, `DEAL_VALUE`, `MACRO_TIMING`, `EXCLUDE_QUARTERS`, `HALF_LIFE`, `SECTOR_FEATURES`), `research/backtest.py` (`--deal-value`, `--winsor`, `--macro`, `--exclude`, `--scales`, `--half-life`, `--sector-features`, `--out`) and `BacktestOptions` (`flowHistory`, `netOfMacro`, `inputTrend`, `inputCap`, `trace`); `ingest/backtest.ts --input <file> --dry` scores a variant without writing. Log new experiments there; keep a change only if it improves skill in both halves.
- **Writes:** `lib/ripple/tuned.json` (chosen settings, read by `settings.ts`), `lib/ripple/backtest.json` (the Accuracy page; the estimator reads its prior width) and `research/backtest.md`. After a backtest that changes the prior width, re-run `npm run estimate`.

## What-if section (`/what-if`, `/what-if/accuracy`)

**Scenarios** (`WhatIfView`) runs the engine in the browser on every change (it's instant), with `RIPPLE_SETTINGS`. The existing pages are untouched. Order: heading → status line (`whatif-meta`: backtest pill linking to Accuracy, links estimated, "Shows direction and strength of likely effects, not price predictions.") → scenario → takeaways → grid with chart and explanation → advisers → About.

- **Inputs** (`ScenarioPanel`): five presets in the panel header ("Rates +1%" = Fed funds and the 10-year both +1 pp, "VIX spike +15", "Tech rally +20%", "Oil crash (Energy −25%)", "Credit crunch (Baa +2)"), then up to four shocks as chips with the editor in the same row. Each shock picks a variable (4 features × 5 sectors, or one of 4 macro inputs) and a size by slider (track fills from zero, green up / red down) or number box, within `SHOCK_RANGES`.
- **Outputs:**
  - `RippleGrid`: sectors × features, green / red with strength relative to the largest knock-on effect; each cell has a small range bar (centre = no change). Q1–Q4 segment, play / pause / replay (1.1 s a quarter) and a scrubber line.
  - `RangeChart`: the selected cell over the quarters, range as a gradient band (a small SVG, not Chart.js), with a level note from the baselines.
  - `WhyPanel`: the selected cell's paths with bars for their share. Each path is one line (its links, e.g. "Valuation → Deal count +1 qtr · Tech → Financials"); "Why" opens the links' reasons, estimates, ranges, sample sizes and data weights (the biggest path starts open).
  - `AdviserPanel`: top 5 banks positioned to rise and to fall, with bars on one scale and the driving sector; a click selects that sector's deal value and shows why.
- **Motion** (all off under `.reduce-motion` / `prefers-reduced-motion`): numbers glide between quarters and scenarios through zero (`useTween`, not `AnimatedNumber`); a scenario change of shape (a preset, a new variable, not a slider drag) sends a ripple wave across the grid from the shocked cells (macro: from the first column), 90 ms a step; the chart morphs and its line draws in; contribution and adviser bars wipe in and resize; chips, rows and why-items rise in.
- **Honesty rules:** a result is marked as an assumption (a dashed ring, explained in the legend) when more than half its knock-on effect runs through links still mostly prior (`assumed`); an adviser row when its driving sector's deal value does. IPO cells show "IPO history loading" until `ipoHistoryReady` (12+ months of priced IPOs before 2021 in `sector_monthly`).
- **Data:** `/api/what-if` (cached an hour) returns baselines from `sector_monthly`. Without the 0002 migration it returns no baselines and the screen still works, minus the level notes.
- Phone: one column, short column headers, the shock tag in place of the range bar.

**Accuracy** (`WhatIfAccuracyView`, from `backtest.json` via `lib/ripple/accuracy.ts`): KPIs (direction right, error vs no change, quarters tested, gain from tuning), takeaways, predicted vs what happened (feature × quarters ahead, average over sectors), a direction grid by feature and quarter ahead with skill bars, what tuning changed (before → now, best setups, the two halves), and the method.

- **Precedent transactions (done):** `/precedents` (`lib/precedents.ts` + `PrecedentsView`). Screen by sector / industry / size / window, untick outliers, summary rows (high, 75th, mean, median, 25th, low), CSV export. A deal drawer's "Precedents" button opens `/precedents?deal=<id>` seeded from that deal (same sector, ⅓×–3× its size). Under the table, "What the banks' DCFs said" (`PrecedentsDcf`): each ticked precedent's target-side DCF value per share (`dcfOf`: the first target-side opinion with a discounted cash flow range) against its offer, drawn on one 0.4x–1.8x-of-offer scale, with the discount rate and terminal growth, and medians (offer vs DCF midpoint, discount rate, growth: `dcfRows`, `summarizeDcf`). - **Fairness-opinion valuation (done):** `ingest/parse/fairness.ts` reads each "Opinion of <Bank>" section of the target's DEFM14A / SC 14D9 / PREM14A: implied per-share ranges by analysis, DCF discount rate / perpetuity growth / terminal multiple, and the bank's fee. Stored as `Deal.fairness`; shown as a football field in the deal drawer's Valuation tab (`components/details/Valuation.tsx`). Ranges are only read inside a bank's section (bids in the background story and termination fees are ignored); a section ends at the next "Opinion of" line, another bank's analysis heading, or a major heading such as the projections. Extend the `SPONSORS` list when a sponsor is missed.
- **Activists (done):** `ingest/activists.ts` reads EDGAR's daily form index (full-text search barely indexes XML 13Ds), fetches each new SCHEDULE 13D whose issuer is US-listed (`primary_doc.xml`, parsed in `parse/thirteend.ts`), and keeps activists only: known funds (`KNOWN_ACTIVISTS`) or a concrete campaign in Item 4 after the SEC checklist boilerplate is stripped (`campaignText`). 13D/A amendments are counted from the index. Stored in `meta` key `activists` (newest 300, ~18 months), shown on `/activists` and on company pages. Missing daily index files return 403: use `getDailyIndex`, not `getText`. Backfill: `npm run ingest -- --only activists --from 2025-01-01`.
- **Deal terms (done):** `ingest/parse/terms.ts` reads deal protections from the target's merger 8-K (Item 1.01), with gaps filled from its merger proxy:
  - **Fees:** the target's break fee and the buyer's reverse fee. The payer comes from defined terms ("Parent Termination Fee"), "X will pay", or who gets paid. Fees outside 0.3%–10% of deal value (12% for reverse fees) are dropped, re-checked after the final value is known. A full-dollar amount ("$5,560,000") is never multiplied by a unit word that follows it.
  - **Go-shop vs no-shop**, including the go-shop length.
  - **Financing:** the financing condition, and the committed lenders. Advisory-only firms are excluded, and lenders are mostly named in the proxy's "Financing of the Merger".

  - **Display:** `lib/terms.ts` builds the stats, lender league and labels. The `/deal-terms` page shows fees by size and sector, the lender league (click to filter) and a deals table. The deal drawer has a "Deal protections" section.
  - Calibrated on real filings: about 94% of public deals have a break fee and about half a reverse fee, at market-typical levels (break 2–4%, reverse 4–7%).
- **Tear sheets (done):** printable Letter one-pagers at `/tearsheet/deal/[id]` and `/tearsheet/company/[id]` (route group `app/(print)`, no terminal shell).
